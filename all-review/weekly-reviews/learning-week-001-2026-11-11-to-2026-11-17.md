## 重点知识与注意事项

### 1. 数据库连接地址取决于程序运行位置

- Windows 或 VS Code 本机终端连接实验库使用 `127.0.0.1:55432`。
- Compose 网络中的应用容器连接数据库使用 `db:5432`。
- Nginx 不参与应用到 PostgreSQL 的数据库连接。
- `host` 能被解析不代表连接成功，`port=None` 表示连接串没有显式端口。

### 2. 事务回滚必须用数据库结果验收

- `flush()` 已执行 INSERT 并取得 ID，仍不等于已经提交。
- 重复设备返回 409 后，应立即按项目编码查库。
- 返回零行表示项目和设备一起回滚。
- 返回项目行且设备编码为 NULL，表示项目可能已经提前提交。
- 修正重试后应验证 HTTP 201，并查到同一个项目下的两台设备。

### 3. HTTP 状态码要按失败环节判断

| 状态码 | 本周场景 |
|---|---|
| 200 | 项目存在，查询成功，即使当前页或筛选结果为空 |
| 201 | 项目和设备创建成功 |
| 404 | 整数项目 ID 通过参数校验，但数据库中不存在 |
| 409 | 请求结构合法，写入时触发已识别的业务冲突 |
| 422 | 路径、查询参数或请求体未通过校验 |
| 500 | 未处理的应用或数据库异常，需要结合日志定位 |

### 4. Alembic 版本和实际表结构要分别核对

- `revision` 生成迁移脚本，`upgrade head` 才修改数据库。
- `alembic current` 显示目标库记录的当前版本。
- 显示 head 不能单独证明应用连接正确，也不能证明实际列结构符合预期。
- 应同时核对 `current_database()`、schema、`alembic_version` 和实际列定义。
- 自动生成的迁移是候选脚本，执行前必须审查。

### 5. 项目 ID、设备 ID 和外键需要明确区分

- 设备列表中的 `items[].id` 通常是设备 ID，不能直接当作 URL 中的项目 ID。
- URL 的 `project_id` 应来自项目记录。
- `devices.project_id` 才是设备归属项目的外键。
- `(project_id, code)` 联合唯一约束允许不同项目使用相同设备编码。

### 6. 分页需要稳定排序和完整验收

- 固定数据下使用 `created_at DESC, id DESC` 保证并列时间的稳定顺序。
- `total` 不随 `page_size` 改变。
- 翻过最后一页时可以得到 `total>0` 和 `items=[]`。
- 完全没有匹配项时得到 `total=0` 和 `items=[]`。
- 游标分页要保存完整排序键，例如 `created_at` 和 `id`。

### 7. Python 和 FastAPI 工程习惯

- VS Code 选择的解释器、`sys.executable` 和 `python -m pip --version` 应指向同一个 `.venv`。
- CSV 错误日志要包含文件、行号、字段和原因，并汇总成功与跳过数量。
- 可复用校验应放在独立函数中，CSV 和 HTTP 层分别转换成日志或 HTTP 响应。
- 测试要隔离数据库状态，避免前一测试的数据影响后一测试。

## 关键问题与标准处理

### 项目存在但查询结果为空，应返回什么

**标准处理**　返回 200，`total=0`，`items=[]`。只有项目本身不存在时才返回 404。

### 三条记录匹配、每页两条，第二页的 total 和 items 是多少

**标准处理**　`total=3`，第二页 `items` 有 1 条。total 在分页前计算。

### 为什么 `flush()` 后拿到 ID，项目仍能被撤销

**标准处理**　flush 只是把 SQL 发给数据库，事务仍未提交。后续失败触发 rollback 时，项目和设备可以一起撤销。

### Alembic 显示 head，为什么还要检查实际列

**标准处理**　版本表只说明该数据库记录了某个迁移版本。还要确认应用连接的是同一个数据库和 schema，并检查实际表结构。

### 字母项目 ID、整数但不存在的项目 ID、超范围查询参数分别是什么状态

**标准处理**　字母项目 ID 返回 422，错误位置为路径参数。整数项目 ID 不存在返回 404。超范围查询参数返回 422，错误位置为对应查询参数。
