### 第 3 题

**原题：** 一次导入先创建项目并执行 `flush()`，此时已经得到了项目 ID。随后发现设备编码重复并执行 `rollback()`。为什么数据库中仍然可以不存在这个项目？应该用什么查询证明回滚成功？

**你的回答：** `flush` 可以拿到 ID 但没有提交，查询该编号的项目及对应设备，不存在就说明回滚成功。

**批改结果：5/5。** 回答正确。

**正确答案：** `flush()` 只把当前事务中的 SQL 发送到数据库，使 ORM 得到数据库生成的 ID，没有提交事务。后续 `rollback()` 会撤销同一事务内的项目和设备写入。按项目业务编号查询项目，再按项目或设备编码查询设备，两者都不存在即可证明回滚成功。

**解释：** ID 已生成不等于事务已经持久化。

### 第 4 题

**原题：** “创建项目”和“批量创建设备”必须全部成功或全部失败。请写出 SQLAlchemy 操作的大致顺序，并指出 `commit()`、`flush()` 和 `rollback()` 分别在什么情况下发生。

**你的回答：** `flush` 可以拿到 ID 但没有提交，`commit` 直接提交到数据库，`rollback` 会撤回一次 session 中未提交的内容，已提交内容不能靠 rollback 撤回。

**批改结果：3/5。** 三个操作的性质基本正确，缺少完整事务顺序。

**正确答案：** 开启一个事务，校验请求和业务约束，添加项目，执行 `flush()` 获取项目 ID，添加全部设备，必要时再次 `flush()` 让数据库约束尽早报错，全部成功后只执行一次 `commit()`。任一校验、唯一约束或数据库操作失败时执行 `rollback()`，并返回相应错误。

**解释：** 整批操作只能有一个最终提交点。中途提交项目会破坏原子性。

### 第 16 题

**原题：** 解释 `User`、`WorkingDirectory` 和 `ExecStart`。若 `ExecStart` 指向已删除的旧虚拟环境，会发生什么？

**你的回答：** `User` 决定用户权限，`WorkingDirectory` 决定用户可以操作的权限，`ExecStart` 指向旧服务会报错。

**批改结果：2/5。** `User` 基本正确，`WorkingDirectory` 和 `ExecStart` 的含义混淆。

**正确答案：** `User` 指定服务进程使用哪个系统账号运行。`WorkingDirectory` 指定进程启动时的当前工作目录，影响相对路径和模块查找。`ExecStart` 是实际执行的解释器及命令。若它指向已删除的虚拟环境，systemd 无法执行该文件，服务启动失败，状态和日志中通常会出现路径不存在或执行失败。

**解释：** `WorkingDirectory` 本身不授予文件权限，权限由文件系统所有者和权限位决定。
