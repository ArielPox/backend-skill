# Redis 后端实战｜课程计划

你已经练过 Docker、FastAPI 和 PostgreSQL。这门课沿用 P29 的项目、设备和告警场景：用 PostgreSQL 保存设备主数据，用 Redis 保存可以重建的读缓存，以及带有效期的请求计数。

结课目标：给 FastAPI 的设备详情接口接入 Redis，亲手验证缓存命中、更新后失效、过期回源和 Redis 停止时的降级。进阶内容再练告警消息的消费与重试。

## 动手实验约定

1. 每课先说本节要做什么，以及看到什么结果才算通过。
2. 用 VS Code 打开 `D:\myskills\Redisskill`，在集成 PowerShell 终端操作。互动教学时，我说“继续”，每次只给一个可验证的步骤。
3. 遇到报错时，先看实际输出，定位是 Docker、连接地址、数据类型还是业务逻辑，再做一个检查。
4. 用自测确认理解。课后把实际命令、输出、报错和复验结果保存到 [实验笔记](./实验笔记/README.md)。

## 实验路线

| 实验 | 动手任务 | 验收标准 |
| --- | --- | --- |
| 01｜启动 Redis 与键过期 | 用 Docker Compose 启动 Redis，用 CLI 读写设备状态和心跳 | 得到 `PONG`；能通过实测解释 TTL 的非负值、`-1` 和 `-2` |
| 02｜给业务数据选结构 | 用 Hash 保存设备状态、Set 维护在线设备集合、ZSet 按分值排列告警；比较 String JSON 和 Hash | 修改单个设备字段、判断设备是否在线、取分值最高的三条告警；用 `SCAN` 分批查看实验键 |
| 03｜FastAPI 接入读缓存 | 用 redis-py 的异步客户端，在应用 lifespan 中管理连接；先查 Redis，未命中再查 PostgreSQL 并回填带 TTL 的缓存 | 同一设备第一次请求查库、第二次命中缓存、缓存到期后再次查库；用日志或查库次数验证 |
| 04｜更新、失效与故障降级 | 设备更新先提交数据库事务，再删对应缓存；设置有限的 Redis 超时时间，模拟 Redis 不可用 | 更新后下次读取返回新值；停掉 Redis 后接口仍可查库；说明并发回填为何可能产生旧缓存 |
| 05｜计数、限流与原子性 | 给告警上报做按项目的固定窗口限流；用 Lua 原子执行计数和首次设置过期 | 小窗口内超额返回 429，过期后可重新请求；并发测试能验证允许数量和计数键 TTL |
| 06｜持久化、内存与排障 | 比较 RDB 和 AOF，用同一命名卷重建容器；在独立实验实例比较 TTL 到期与内存淘汰 | 重建后验证指定数据是否保留；通过 `INFO` 中的计数区分过期与淘汰 |
| 07｜项目综合验收 | 复用设备接口，补齐项目隔离、缓存失效、异常处理和集成测试 | 两个项目使用相同设备 ID 时缓存不串；用测试覆盖命中、更新、过期和 Redis 断开 |
| 选修｜告警消息与 Streams | 对比 Pub/Sub 和 Streams；用消费组领取、确认和重新认领待处理告警 | 模拟消费者在确认前退出，恢复后处理待确认消息；用告警 ID 实现业务去重 |

## 现在从这里开始

[实验 01｜启动 Redis 与键过期](./实验01-启动Redis与键过期.md)已经写好，其余实验先按路线推进。第一课只用 Docker 和 `redis-cli`，从第三课开始接 FastAPI。

后续请求链路：设备详情请求 → FastAPI → 查 Redis；命中就返回，未命中则查 PostgreSQL、回填 Redis 并返回。缓存键包含项目 ID 和设备 ID。接口要先校验请求者是否能访问该项目，再读取缓存。
